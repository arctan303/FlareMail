# 给助手一个独立邮箱

为自己的助手分配一个邮箱地址，让邮件成为任务和资料的入口。FlareMail 提供个人 CLI API 与收件 Webhook：助手可以查询、读取和回复邮件，接收端也可以在新邮件就绪后收到通知，再安排助手处理。

[了解 CLI 与 Webhook](/docs/zh/cli) · [体验邮箱界面](/inbox) · [部署自己的邮箱](/docs/zh/deployment)

## 先让助手能读写邮件

在自己的实例中创建助手使用的邮箱地址，并在个人设置生成 CLI Token。助手通过该 Token 查询邮箱、筛选未读邮件、按 ID 获取正文或附件，以及发送和回复邮件。

Token 访问所属用户的数据。若要让助手只使用自己的账号，应为它创建独立成员，而不是共用管理员的 Token。HTML 邮件提供可读正文，增量查询可以减少反复拉取完整列表。接口与示例见 [CLI / Agent](/docs/zh/cli)。

## 新邮件到达后通知接收端

在邮件和附件就绪后，Webhook 会向你配置的公网 HTTPS 接收端发送事件，包含事件 ID、邮件 ID 与收件邮箱。接收端验证独立共享密钥、可靠入队后返回成功，再用自己的 CLI Token 获取邮件内容。

接收端按事件 ID 去重，并根据自己的执行策略排队、合并通知或唤醒助手。一次通知如何转成一次助手运行，由接收端实现；FlareMail 提供事件和投递记录。失败通知会进行有限重试。

外部来信和同站内部投递都能产生通知。配置、启停、密钥轮换、测试通知和投递记录可在 CLI 或网页中管理，两边使用同一份设置。

## 按需选择通知范围

可以选择通知全部发件人，也可以只通知地址白名单中的发件人。过滤只影响通知，名单外的邮件仍按原有规则收取；白名单模式下空名单不触发。

当前白名单按邮件 From 中的完整地址匹配，不区分大小写。这是地址过滤，不代表发件人已经通过身份认证；接收端仍需决定哪些邮件内容可以成为助手指令。

## 联调时确认什么

先发送测试通知，确认回调地址可达、共享密钥一致、接收端能入队并返回成功；再从外部邮箱发送一封邮件，检查事件、正文读取和助手处理是否连贯。接收端若只有 IPv6，需要单独验证实际网络链路。

Webhook 与 CLI 能力已在本地验证；真实 IPv6 回调和助手端到端唤醒仍待联调。部署版本需要包含对应能力，邮箱界面的[在线体验](/inbox)不提供真实 CLI API 或外部回调。

## 分享接入结果

欢迎在 [Discussions](https://github.com/arctan303/FlareMail/discussions)介绍所接入的助手、接收端运行环境、希望怎样触发处理，以及在哪一步遇到了困难。发现可复现的问题时，在 [Issues](https://github.com/arctan303/FlareMail/issues)附版本、步骤和已脱敏的投递结果。

公开反馈请隐去 Token、Webhook 共享密钥、私人回调地址和邮件正文；安全问题使用[私密报告](https://github.com/arctan303/FlareMail/security/advisories/new)。

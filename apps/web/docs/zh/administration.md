# 管理员配置

一个人使用时，自己的邮箱账号同时负责实例管理。先完成[部署](/docs/zh/deployment)与真实收发测试，就可以开始使用；品牌、Google 登录和受邀成员按需配置。

## 添加受邀成员（可选）

在左侧「用户列表」添加用户，填写邮箱、名称、初始密码及需要的额度。邮箱域名应先在「系统设置 → 邮箱域名」登记，并完成收信路由与发信配置。

当前邀请制由管理员创建账号并安全交付登录地址、邮箱和初始密码，不会自动发送邀请邮件，也没有公开注册或邀请链接。成员第一次用密码登录后，应修改初始密码。停用、删除与物理删除的影响不同，执行前阅读确认提示；物理删除会清理相关邮件与附件，不能当作普通停用。

## 管理邮箱域名

先在「系统设置 → 系统维护」完成数据库 **328** 更新，再到「邮箱域名」管理已有域名。新增域名仍无需重新部署；新增后也要配置 DNS、Email Routing 和发信服务。

- **停用 / 启用**：停用后禁止该域名新增邮箱及收发，已有用户仍可登录和查看历史邮件；之后可重新启用。已经在途的网络投递无法撤回。
- **修改域名**：改成一个尚未登记的新域名，同时迁移原域下全部邮箱，保留原启停状态。例如 `a@old.example` 改为 `a@new.example`。
- **迁移邮箱**：把原域全部邮箱迁到已登记、已启用的目标域，保留邮箱前缀；原域随后停用。目标地址被占用时，包括保留的已删邮箱，整次迁移会被阻止，不会自动合并。
- **删除域名**：只允许删除没有关联邮箱或登录账号的域名，且至少保留一个登记域名。有邮箱时先迁移；删除域名配置不删除邮件或附件。

每次变更先预览受影响邮箱、登录用户、邮件和附件数量，再确认执行。其他人修改域名或关联邮箱后，需要重新预览。迁移保留用户、邮箱及历史数据的归属和原始邮件内容；已删除的邮箱记录也一起迁移。主登录邮箱发生变化的用户须使用新地址和原密码重新登录，并重新生成 CLI Token；迁移未兑换的授权码失效。本地草稿仍归属于原用户。

新域名的 DNS、收信路由和发信凭据需要另配，旧域名的发信凭据不会复制。迁往已有目标域时保留目标自己的凭据。邮箱 Webhook 配置随邮箱保留，旧地址尚未完成的通知取消，新的通知使用新地址；已经在途的通知无法撤回。

## 检查收发与投递回传

「系统设置 → 邮件收发」可检查登记域名的MX、SPF、DMARC与指定选择器的DKIM记录，查看启停、凭据和绑定状态。检查不可用时保留明确提示，不把查询失败当作没有记录。公开DNS查询使用Cloudflare DoH；DKIM选择器以服务商给出的值为准。

真实发信测试须选择自己的发件邮箱并填写目标地址，点击后按正常额度发送一封测试邮件；在目标邮箱确认收到。收信测试会给出目标地址和唯一主题，从外部邮箱按该主题发送，再点击检查。DNS、绑定或服务商接受都不能代替实际收发验证。

Resend回传在同一分区配置：复制回调地址到Resend的Webhooks，订阅界面列出的投递事件，把该端点的 `whsec_...` 签名密钥保存到FlareMail。服务端按原始请求体验证签名、时间和重复事件；密钥不返回到读取响应。发件人可在已发送邮件中查看逐收件人的事件，部分收件人送达不会被记为全部送达。该回传与通知助手的收件Webhook互相独立。[Resend验签说明](https://resend.com/docs/webhooks/verify-webhooks-requests)

已保存Resend Key旁可选择清除，保存当前分区并完成敏感操作验证后生效；取消或重置不会清除服务器凭据。

## Google 登录（可选）

1. 在 Google Cloud 创建 OAuth 的 Web application 客户端，按 Google 提示配置授权界面与测试用户或发布状态。
2. 添加两个完整的 Authorized redirect URI，把示例域名换成实际网页地址：

~~~text
https://mail.example.com/login/oauth/callback
https://mail.example.com/oauth/bind/callback
~~~

3. 在「系统设置 → 登录与授权」保存 Client ID、Client Secret，再启用 Google 登录入口。
4. 成员先用邮箱密码登录，在个人设置绑定自己的 Google 账号，之后才可使用 Google 登录。

Google 登录不会自动创建邮箱成员。登录入口开关与个人账号绑定不同：已配置凭据时，关闭入口仍可在个人设置绑定或解绑。解绑会使现有会话及个人 CLI Token 失效，需要重新登录。改变网页域名时同步修改 Google 回调地址。[Google 配置说明](https://developers.google.com/identity/protocols/oauth2/web-server)

更换已绑定的 Google 账号后，发起操作的当前网页会话保留，其他已有网页会话（包括密码登录）需要重新登录。首次绑定或再次绑定同一 Google 账号不会触发这项撤销。旧实例需先完成数据库 326 更新才能更换绑定。

## Turnstile（可选）

在 Cloudflare 创建 Turnstile widget，将正式网页主机名加入允许列表。把 Site Key 与 Secret Key 保存到「登录与授权」，按界面启用验证。Site Key 用于浏览器，Secret Key 只交给服务端；两者不能互换。启用后从退出登录的页面验证是否能正常加载与登录。[官方步骤](https://developers.cloudflare.com/turnstile/get-started/)

## 品牌与服务开关

「站点品牌」管理名称、图标、登录页和 PWA 外观；品牌文字不会自动翻译。「核心服务」管理全站服务开关。修改后保存对应分区，并检查前台效果。

收信过滤、未知收件人及转发见[收信配置](/docs/zh/receiving)，发信通道见[发信配置](/docs/zh/sending)。不要为了接入脚本开放额外 CORS 来源；普通 CLI 使用个人 Token 即可。

## 网站授权与敏感操作

把 FlareMail 作为自己网站的授权服务时，另按[OAuth 接入](/docs/zh/oauth)配置。这与 Google 登录及 CLI Token 独立，默认关闭。

涉及密钥、主邮箱迁移和数据删除的操作按提示重新验证密码。管理员迁移主邮箱后，用户需要使用新邮箱与原密码重新登录；不要把邮箱置顶或写信选择发件地址当作登录身份迁移。
